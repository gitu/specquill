# Bring-your-own-token forge authentication

The v1 deployment authenticates with **personal access tokens from the
deployment's git host** (GitLab or GitHub). The user's token is the only
credential in the system: it proves identity, decides the deployment role,
and performs every git and forge-API operation on that user's behalf.

> **REQ-024.1 · MUST** — Login SHALL verify the token against the forge's
> identity API; the forge account (stable numeric id) is the user identity,
> and the account's name/email become the git author on every commit.

> **REQ-024.2 · MUST** — The deployment role SHALL be derived from the
> user's actual permission on the main project at every login (developer →
> editor, maintainer → maintainer, owner/admin → admin); a token without
> read access to the main project SHALL be rejected. This role gates login
> and governs the configured projects; on dynamically opened repositories
> ([REQ-025](REQ-025.md), where enabled) the user's forge permission on
> each repository governs instead (REQ-025.3).

> **REQ-024.3 · MUST** — The server SHALL NOT persist tokens: a token may
> exist server-side only in memory, scoped to a session, and vanishes with
> logout, session expiry or a restart. The browser keeps the token
> (localStorage) and re-authenticates transparently.

> **REQ-024.4 · MUST** — Server-side repository state SHALL be isolated per
> user: every clone and fetch runs with the requesting user's token into
> that user's own storage, so content one token can reach is never served
> to a session holding a different token.

> **REQ-024.5 · MUST** — The default branch SHALL only move via the forge:
> the in-app merge is disabled; the app pushes the workspace branch with
> the user's token and opens (or re-uses) a merge request / pull request
> there. (With [REQ-025](REQ-025.md).10, workspace-branch commits are
> pushed as they happen — propose then only creates or re-uses the MR/PR.)

> **REQ-024.6 · SHOULD** — The login page SHALL guide token creation: name
> the required scopes and deep-link to the forge's token-creation page,
> prefilled where the forge supports it.
