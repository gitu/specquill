# Change history derived from git, in workspace terms

The workspace answers "what changed" from its own history. Commits are read
from git, every touched path is classified through the **current** workspace
configuration, and each document's change is expressed the way the document
is written — properties that moved, normative statements added, dropped or
reworded — rather than as diff lines. Pending work (uncommitted drafts,
commits ahead of the default branch, the open merge request) is a separate,
branch-scoped view.

> **REQ-027.1 · MUST** — The workspace SHALL expose its commit history
> scoped to the project's content root ([REQ-003](REQ-003.md)): a commit that
> touches nothing inside the root is not part of this workspace's history,
> and every path SHALL be reported project-relative. Reads SHALL require only
> the viewer role and SHALL NOT mutate the repository.

> **REQ-027.2 · MUST** — Every changed path SHALL be classified into its
> document family using the same rule as the document model
> ([REQ-012](REQ-012.md)) — frontmatter type first, folder as fallback — so
> that deleted and renamed-away paths, which no longer exist in the
> workspace, still read as the family they belonged to. Renames SHALL carry
> both sides.

> **REQ-027.3 · MUST** — For a selected commit the workspace SHALL derive,
> per markdown document, a **semantic delta**: frontmatter properties whose
> value changed (with before and after), normative statements
> (`> **REQ-042.3 · MUST** — …`) added, removed or reworded, and sections
> that came or went. A document with no such structure SHALL fall back to the
> textual diff rather than claiming nothing changed.

> **REQ-027.4 · MUST** — Both sides of a delta SHALL be read from the object
> database at the commit and its first parent, never from a worktree, and a
> root commit SHALL diff against the empty tree.

> **REQ-027.5 · SHOULD** — The feed SHOULD be filterable by document family,
> author and time window, and SHOULD roll each commit up in model terms
> ("3 requirements · 1 spec") rather than by file count.

> **REQ-027.6 · MAY** — When an AI tier is configured, a commit MAY carry a
> one- or two-sentence summary generated from its semantic delta (not from
> the raw diff) on the quick model tier, cached per commit. Absence of a
> configured model SHALL degrade the feed to a working, summary-less view.

> **REQ-027.7 · MUST** — Pending changes SHALL be shown separately from
> history, per branch, in the order work travels: uncommitted worktree
> drafts, then commits ahead of the default branch with their merge or
> propose action ([REQ-008](REQ-008.md), [REQ-024](REQ-024.md)), then the
> open merge request on the forge.
