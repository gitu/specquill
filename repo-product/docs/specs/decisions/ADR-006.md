# Embedded SQLite as the metadata store

## Context

[ADR-001](ADR-001.md) chose Postgres when the target was hosted
multi-tenancy on disposable instances. Both premises are gone: a deployment
now serves exactly one tenant, and the supported shapes are a self-hosted
instance with a persistent directory and a developer running the binary
locally. The server is single-instance by construction anyway — the collab
hub is in-process, worktrees are on local disk, and the data directory is
lock-held — so Postgres's concurrency was never being used.

## Decision

Use an embedded SQLite database at `<data_dir>/specquill.db`, via a cgo-free
driver so the binary stays statically linked. WAL journaling, enforced
foreign keys, and write-locked transactions.

Do **not** keep Postgres as a second backend. A backend that is not exercised
by every test run rots silently — the Postgres-only advisory lock that had
survived untested in the merge path is the cautionary example — and two
backends make otherwise-identical deployments diverge in code path rather
than only in configuration.

## Consequences

- The developer-local deployment has no service to run — one binary, one
  config file.
- `data_dir` must be persistent: it holds the clones (rebuildable) *and* the
  database (not). It is what gets backed up.
- Deployment targets without a persistent disk are excluded. This is why the
  Cloud Run pipeline was dropped rather than adapted.
- Dev and production run the same storage engine, so storage bugs reproduce
  locally.
